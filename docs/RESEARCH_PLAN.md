# 当前研究计划：SCoRe-first 方法研究

**状态：ACTIVE**
**生效日期：2026-09-21**

这份文件替代此前“广泛比较旧方法并写分析论文”的路线。历史实验仍有效，但不再决定当前任务顺序。

---

## 1. 论文目标

最终成果必须是一篇**有新方法的视觉 token 压缩论文**。诊断、复现、Oracle 和压力测试只是内部研发过程，用来回答两个问题：

1. SCoRe 的优势能否在我们环境中忠实复现？
2. 它是否存在足够大、可被一个清晰机制解决的缺口？

不以“分析若干旧方法的优缺点”作为最终论文贡献，也不要求新方法在所有表格上超过所有同期工作。更现实、也更可信的目标是：

- 至少在一个重要场景或成本区间形成新的 Pareto 前沿；
- 机制可解释，改进在多数据集/预算上稳定；
- 公平击败 2024 年强基线，并与 SCoRe 及提交时最近工作正面对比；
- 对没有提升的设置如实报告。

---

## 2. 当前强基线

当前研究锚点是：

> **SCoRe: Salience-Coverage Reduction for Vision Token Pruning in Vision-Language Models**
> Tong Xu, Hailong Shi, Xingyu Gao — **CVPR 2026**

官方页面：[CVF Open Access](https://openaccess.thecvf.com/content/CVPR2026/html/Xu_SCoRe_Salience-Coverage_Reduction_for_Vision_Token_Pruning_in_Vision-Language_Models_CVPR_2026_paper.html)

选择它不是因为“SOTA”三个字，而是因为它满足本项目的起点要求：training-free、pre-LLM、结构清楚，并在论文设置中直接比较且优于 SparseVLM、VisionZip、VisPruner 等我们关心的工作。

边界：这不证明它在所有新模型、动态分辨率、真实时延或所有 2026 预印本中都最强。正式投稿前必须重新做一次同期工作检索。

---

## 3. 要检验的核心缺口

SCoRe 在给定固定 `K` 时，优化一组 token 的 salience 与 coverage。当前最值得优先检验的限制是：

> **固定 `K` 假设每个样本需要相同数量的视觉证据，但实际需求可能随图像复杂度、问题类型和文字密度显著变化。**

如果成立，简单图像上固定 `K` 浪费计算；复杂、OCR 或细粒度图像上固定 `K` 又可能不足。

候选方法不是另加一个 router，而是把固定基数目标

```text
max f(S)  subject to |S| = K
```

改写为带选择成本的目标

```text
max f(S) - λ|S|
```

并在贪心选择时依据边际收益停止。直觉上，这让 SCoRe 自己的 salience–coverage 目标同时回答“选哪些”和“选多少”。

这只是候选机制。未过 Oracle 前不得把它写成项目已确定的创新。

---

## 4. 必须同时审计的替代缺口

为避免只盯一个假设，S1 还需用小规模实验检查：

1. **表示空间**：用于 coverage 的特征空间是否保留了 OCR/细粒度语义；
2. **query 条件**：SCoRe 的选择对问题是否盲目，以及这种盲目是否造成稳定错误；
3. **真实开销**：选择器在高分辨率或动态分辨率下是否抵消 token 节省；
4. **跨模型稳定性**：在较新架构上是否仍保持论文中的优势。

这些是竞争性假设，不是准备全部加入方法的四个模块。只选择证据最强、最简洁的一条。

新颖性警告：单纯加入 query relevance 很可能不足，因为 CoverPruner 等同期工作已经探索 query-weighted coverage。任何方法立项前必须检索最近工作并写清差异。

## 5. 阶段与决策门

### S0 — 忠实复现

- 锁定论文版本、补充材料、官方代码/commit 和依赖；
- 先复现论文设置，不先改写为 tcbench 版本；
- 再做受控接入，保持 Track A / Track B 分离；
- 关键设置复现偏差超过 `1.0` 点时，先排查，不进入创新结论。

### S1 — 缺口验证

- 在 `K ∈ {32, 64, 128, 192}` 上建立逐样本曲线；
- 定义每样本“最小可接受 K”，构造只用于上界估计的 Oracle；
- 与最强固定 `K` 在相同平均 token 或相同真实成本下比较；
- 对 OCR、细粒度、普通 VQA 和图像复杂度分组；
- 同时记录 selector overhead、TTFT 与端到端时延。

### Go / No-Go

满足任一条件才进入 S2：

- Oracle 在相同平均成本下比最强固定 `K` 高至少 `1.0–1.5` 点；
- 或在质量下降不超过 `0.5` 点时节省至少 `15%` 平均视觉 token / TTFT。

若不满足：fixed-`K` 方向否决，回到 §4 选择下一个缺口；不降低阈值，不用挑子集挽救。

### S2 — 方法实现

- 先冻结方法公式、停止规则和最多三个超参；
- 只实现一个核心机制；
- 与 fixed-`K` SCoRe 在相同平均 token、相同 TLB 和相同真实成本三种口径下比较；
- 必做固定阈值、不同停止信号、Oracle 上界和 selector 开销消融。

### S3 — 论文级验证

- baseline：SCoRe + 最近的直接同期工作 + 少量公认 2024/2025 强基线；
- 至少覆盖普通 VQA、OCR/文档、细粒度或感知类任务；
- 至少两个模型家族，其中一个应是较新的动态分辨率 VLM；
- 报告质量—TTFT/时延/显存 Pareto，而不只报 token 数。

---

## 6. 成功标准与自我约束

- 不要求在每个 benchmark 都超过最新方法，但不能只在一个小表格上偶然涨点。
- 核心方法模块数不超过 2，新增超参不超过 3。
- 贡献小于 `0.5` 点且没有效率收益的模块删除。
- 任何主结论必须跨至少两个数据集或两个模型/预算区间成立。
- 如果新方法只改变 token 数而真实 TTFT 不改善，不能声称更高效。
- 如果 SCoRe 忠实复现失败，先解决复现，不在错误基线上做创新。
